# astrbot_plugin_pity_active_reply — 保底递增式主动回复

替代 AstrBot 原生「主动回复」的纯概率抽签：**连续没插话时概率逐条升高，一旦主动插话或被 @ 被动回复，概率重置回初始值**。从而规避纯随机"某段时间一直主动接话、某段时间又从不接话"的尴尬。

已在 AstrBot 桌面版 v4.29.4（qq_official 平台）源码级核对 API。

## 概率模型

对每条**没有唤醒 bot**（未 @、未命中唤醒词/命令）且含实际内容的群消息抽签：

```
p = min(base_prob + increment × 连续未插话条数, max_prob)   # 硬保底开启且计数≥阈值时 p=1
```

- 抽中 → 以当前对话上下文主动回复该消息，计数清零
- 未中 → 计数 +1，下一条概率升高
- 群内出现 @ bot / 唤醒词 / 命令 / 按钮交互（被动回复路径）→ 计数清零

默认参数（0.05 + 0.03N，上限 0.4）下：约 88% 的概率在 10 条内、99% 在 20 条内会主动插话一次；刚回复过则立刻回到 5% 的低调状态。

## 安装

放入 AstrBot 数据目录 `data/plugins/astrbot_plugin_pity_active_reply/`，在 WebUI 插件管理中重载。

## 启用前必须做的一件事

> **关闭原生主动回复**：WebUI → 配置 → 其他配置 → 群聊上下文感知 → 主动回复开关 → 关闭。
>
> **保持「群聊上下文感知」本身开启**——本插件触发回复时依赖它注入群聊历史，且两者是不同的开关。

若检测到原生主动回复仍开启，插件会每 10 分钟在日志警告一次并暂停工作（宁可不动，也不双重回复）。

## 配置项

所有配置均在 **WebUI → 插件管理 → astrbot_plugin_pity_active_reply → 配置** 中修改，无需改代码；保存后如未见生效，在插件管理中重载一次本插件即可。概率公式 `p = min(base_prob + increment × 连续未插话条数, max_prob)` 的三个参数就是下表前三行。

| 配置 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `base_prob` | `0.05` | 初始/重置后的起步概率 |
| `increment` | `0.03` | 每条未插话消息的概率增量（0 = 退化为固定概率，即原生行为） |
| `max_prob` | `0.4` | 递增封顶 |
| `hard_pity_count` | `0` | 连续 N 条未插话后下一条必回（0 = 关闭） |
| `decay_minutes` | `0` | 群消息间隔超过 N 分钟则计数先清零（0 = 关闭） |
| `whitelist` | `[]` | 群白名单：群号 / QQ 官方群 openid / 完整 umo，留空 = 所有群 |

## 行为细节

- 计数仅存内存：重启 AstrBot 后从 0 开始（无伤大雅）
- 抽签概率始终钳制在 0~1：即使误把 base_prob/max_prob 填成大于 1 的值，也不会退化为每条必回
- 重置发生在**抽中触发时**（而非确认发送成功后）；若触发时 LLM 报错（无提供商/无活跃对话等）计数同样已清零，日志会给出具体原因
- 白名单等判断在前、抽签在后，不浪费计数
- 抽中后的回复链路与原生主动回复完全一致（`event.request_llm` + 当前对话），人格、群聊上下文注入、群成员发言标注插件等全部照常生效
- 与平台无关：qq_official / aiocqhttp(NapCat) 等均可；qq_official 下群 ID 为 group openid
